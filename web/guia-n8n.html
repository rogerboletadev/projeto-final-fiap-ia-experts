Como rodar o Squad Cost Copilot no n8n

Quatro nós e nenhum arquivo para ler. No fim você tem um chat que recebe o pedido em texto e devolve a comparação entre as consultorias.

Passo a passo Problemas comuns Por que n8n

Passo a passo

  1. Suba o n8n

    Se você já tem n8n (Cloud ou instalado), pule para o passo 2. Para testar na sua máquina com Docker:

    docker volume create n8n_data

docker run -d --restart unless-stopped --name n8n \
  -p 5678:5678 \
  -v n8n_data:/home/node/.n8n \
  docker.n8n.io/n8nio/n8n

    Abra http://localhost:5678 e crie a conta de administrador. Também dá para usar o n8n Cloud, sem instalar nada.

    Esse modo serve só para testar. Para uso de verdade, o n8n precisa de HTTPS, banco Postgres e backup. Veja a documentação oficial para a versão atual das instruções.

  2. Crie a credencial do Gemini

    Gere uma chave de API no Google AI Studio. No n8n, abra Credentials, crie uma nova credencial, procure por Google Gemini e cole a chave.

    Não coloque a chave em arquivo do projeto, em repositório ou em print.

  3. Adicione o gatilho de chat

    Crie um workflow novo e adicione o gatilho When chat message received (Chat Trigger). Não precisa mudar nada. A mensagem do usuário chega em {{ $json.chatInput }}.

  4. Adicione o Gemini para extrair o pedido

    Adicione o nó Google Gemini com a ação Message a model e escolha a credencial do passo 2. Escolha um modelo Gemini da lista disponível na sua conta.

    Prefere Claude? Use o nó Anthropic com a mesma System Message e uma credencial da Anthropic. O nó Code lê a resposta dos dois sem ajuste.

    Na mensagem do usuário, use:

    {{ $json.chatInput }}

    Na instrução de sistema (System Message, dentro de Options) cole o prompt abaixo. Se o seu nó não tiver esse campo, cole o prompt no início da mensagem. Se houver opção de saída em JSON, ative.

    
          
    
          
    O prompt já traz a lista de cargos do catálogo. Se você mudar os CSVs, rode node scripts/build.js e copie de novo. Ele assume que júnior, pleno e sênior valem N1, N2 e N3, uma hipótese que precisa de confirmação.

Problemas comuns

      

        
O chat responde vazio

        
O Chat Trigger devolve o campo output do último nó. Confira que o Code é o último nó do fluxo e abra a saída dele para ver se o campo existe.


        
Aparece "Não entendi o pedido"

        
O Gemini não devolveu JSON puro. Abra a saída do nó Gemini e veja o que veio. Se vier texto solto, reforce no prompt a regra de responder somente JSON ou ative a saída em JSON do nó.


        
O Code dá erro ao ler a resposta do Gemini

        
Dependendo da versão, o texto vem em outro campo. Veja em que campo ele está na saída do nó Gemini e ajuste o bloco "Entrada", no fim do código. Ele já tenta text, output, content.parts[0].text (Gemini) e content[0].text (Claude).


        
Erro de modelo não encontrado

        
Troque o modelo na lista do nó Gemini por um que sua conta tenha disponível.


        
O total não bate com o esperado

        
Confira se o prompt e o código foram copiados depois da última alteração nos CSVs. Os dois são gerados pelo mesmo build.

      

    


    

      
Por que o n8n é bom para este projeto

      
    
        
  • 
          
    Você enxerga o fluxo inteiro
    
          
    Cada etapa é um nó, e dá para abrir a entrada e a saída de cada um. Para depurar uma resposta errada do modelo e para explicar o projeto numa apresentação, isso economiza muito tempo.
    
        
    • 
        
  • 
          
    Os conceitos do curso já viram nós
    
          
    O n8n organiza a parte de IA em nós principais (agente, chain, vector store) e nós auxiliares (modelo de linguagem, memória, ferramenta, retriever, embeddings, document loader, text splitter). RAG, chunking e banco vetorial têm peça pronta, o que acelera a v2.
    
        
    • 
        
  • 
          
    Mistura low-code com código de verdade
    
          
    O nó Code roda JavaScript, então a regra de custo fica em código testável e o modelo só entende o pedido. É o desenho deste projeto.
    
        
    • 
        
  • 
          
    Dá para rodar no seu próprio servidor
    
          
    A edição Community pode ser instalada por você, o que ajuda quando o dado é sensível e não deve passar por uma plataforma de terceiros. Você paga o servidor, não por execução.
    
        
    • 
        
  • 
          
    Fala MCP
    
          
    O nó MCP Server Trigger transforma ferramentas e workflows do n8n em um servidor MCP, que outros agentes podem chamar. Isso encaixa na ideia de expor o cálculo de custo como ferramenta, prevista no roadmap.
    
        
    • 
        
  • 
          
    Gatilhos e conexões para o que vem depois
    
          
    Chat, webhook e agendamento são gatilhos nativos. Os alertas de alocação e a leitura de dados de outros sistemas entram como novos nós, sem reescrever o fluxo.
    
        
    • 
      


      
Onde o n8n tem limite

      
    
        
  • 
          
    Fluxos de decisão complexos
    
          
    Para um agente que escolhe caminhos, mantém estado e se corrige, um grafo em código (LangGraph) dá mais controle. O n8n é ótimo para protótipo e orquestração. Por isso o roadmap leva o cérebro do agente para o LangGraph na v3.
    
        
    • 
        
  • 
          
    Testes e versionamento
    
          
    Um fluxo visual é mais difícil de testar e de revisar em pull request do que código. Por isso o motor de cálculo deste projeto vive fora do n8n, com testes, e o n8n só o chama.
    
        
    • 
        
  • 
          
    Licença
    
          
    O n8n é "source-available", não open source clássico. Usar internamente e para estudo é tranquilo, mas a licença restringe hospedar o n8n para clientes pagantes. Se este projeto virar um produto vendido, confira a licença antes.
    
        
    • 
        
  • 
          
    Produção dá trabalho
    
          
    Para sair do modo de teste são necessários HTTPS, banco Postgres, backup e atualização de versão. Quem não quer cuidar disso pode usar o n8n Cloud.
